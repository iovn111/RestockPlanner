## 2026-10-23 — Тема и рамки проекта
- Решение: система планирования закупок у поставщика для малых селлеров WB/Ozon с восстановлением спроса при дефиците и прогнозом новинок.
- Причина: подтверждённый спрос на рынке; у конкурентов («Поставлено!», SelSup и др.) дефицит учитывается грубо, новинки — вручную; задача закупки у поставщика закрыта слабее распределения по складам.
- Альтернативы: RAG-бот по документам, голосовая CRM, распознавание документов, анализ отзывов — отклонены из-за насыщенности рынка или доминирования крупных игроков.
- Влияние: весь проект.

## 2026-10-23 — Методы научной части
- Решение: восстановление спроса через коэффициент доступности по размерам + заполнение по «чистым» дням; новинки — аналоги из каталога селлера + смешивание w = n/(n+k); риск — по эмпирическим ошибкам прогноза.
- Причина: моменты дефицита известны напрямую; продажи — малые целые числа; малый каталог селлера; требование объяснимости.
- Альтернативы: Тобит-регрессия и EM (нарушение предпосылок, сложность объяснения); глобальная модель LightGBM (мало товаров у малого селлера) — на диплом.
- Влияние: core/, experiments/.

## 2026-10-23 — Данные
- Решение: основной путь — открытые датасеты FreshRetailNet-50K, VISUELLE/VISUELLE 2.0, H&M («виртуальный селлер»); реальный селлер — опционально.
- Причина: открытых данных WB/Ozon нет; публичный доступ к данным WB ограничен.
- Альтернативы: парсинг маркетплейса — отклонён (правила площадки, нестабильность).
- Влияние: data/, эксперимент, раздел ограничений в курсовой.

## 2026-10-30 — Формат продукта: десктопное приложение для Windows
- Решение: десктопное приложение на PySide6, работающее офлайн; данные хранятся локально в SQLite; интернет нужен только для загрузки данных по API. Ежедневные снимки остатков собирает программа restock-sync через Планировщик заданий Windows. Распространение — установщик .exe (PyInstaller + Inno Setup).
- Причина: данные селлера не покидают его компьютер (отличие от облачных конкурентов); не нужны сервер и затраты на хостинг; вычисления лёгкие и выполняются локально.
- Альтернативы: веб-сервис (нужны сервер, хранение чужих ключей, расходы); pywebview с HTML-интерфейсом (выбран нативный интерфейс PySide6).
- Ограничения: только Windows; история остатков зависит от того, включён ли компьютер; неподписанный .exe может вызывать предупреждение SmartScreen.
- Влияние: структура приложения (gui/, services/, sync/, notify/, packaging/), этапы 6–7 плана.

## 2026-11-03 — Маркетплейс MVP: Wildberries
- Решение: в MVP реализуется адаптер только для Wildberries; реального селлера пока нет, поэтому основной режим — демо-магазин.
- Причина: рамки MVP — один маркетплейс; у WB крупнейшая доля малых селлеров одежды.
- Альтернативы: Ozon — на диплом (второй маркетплейс).
- Влияние: data/ (адаптер WB делается по официальной документации на Этапе 6), сценарий первого запуска.

## 2026-11-03 — Данные демо-магазина
- Решение: товары, атрибуты и продажи берутся из «виртуального селлера» H&M; остатки, размеры, дефициты и процент выкупа моделируются. В интерфейсе данные помечаются как демонстрационные.
- Причина: ни один открытый датасет не содержит одновременно размеров, остатков и новинок; в H&M нет остатков, FreshRetailNet — свежие продукты без размеров.
- Альтернативы: FreshRetailNet как демо (не похож на селлера одежды, длинный срок поставки неуместен); полностью синтетические данные (теряется реалистичность спроса).
- Влияние: data/ (адаптер демо-магазина), юзабилити-тест, раздел ограничений.

## 2026-11-03 — Сигнал спроса: заказы, а не выкупы
- Решение: прогнозируются заказы (units_ordered). Расход склада = прогноз заказов × процент выкупа; процент выкупа вычисляется автоматически (товар → категория → значение по умолчанию).
- Причина: заказ отражает желание купить, то есть спрос; выкуп зависит ещё от размера и качества и для одежды занижает спрос в разы.
- Допущение: невыкупленный товар возвращается на склад в пределах горизонта планирования. Проверить по официальной документации WB, какие поля это отражают (Этап 6).
- Альтернативы: прогноз выкупов напрямую (смешивает спрос и возвраты, хуже для восстановления спроса).
- Влияние: модель данных (units_ordered, units_bought_out), core/order_quantity.

## 2026-11-03 — Политика заказа: периодическая проверка (R, S)
- Решение: N = max(0, расход за (L + R) + страховой запас − остаток − в пути на склады МП − уже заказано у поставщика). L — срок поставки (единственная обязательная настройка), R — период до следующего заказа, по умолчанию 30 дней. Дата «заказать до» — момент, когда прогнозный остаток достигает точки заказа (расход за L + страховой запас). Цвет: красный — дата наступила, жёлтый — в ближайшие 7 дней.
- Причина: классическая модель управления запасами, легко объяснима; малые селлеры с поставками из Китая обычно заказывают раз в месяц.
- Альтернативы: точка заказа (s, Q) с непрерывным контролем (требует фиксированного объёма партии); EOQ (нужны издержки заказа, которых селлер не знает).
- Гипотезы: R = 30, порог «жёлтого» 7 дней, целевой риск 5% — подбираются/проверяются в симуляции (Этап 5).
- Влияние: core/order_quantity, experiments/simulation, gui (необязательное поле «Уже заказано у поставщика»).

## 2026-11-03 — Деньги считаются по цене продажи
- Решение: упущенные продажи и замороженный капитал выражаются в рублях по цене продажи; себестоимость в MVP не запрашивается.
- Причина: требование одной обязательной настройки; цена продажи доступна из данных.
- Ограничение: замороженный капитал по цене продажи завышен относительно себестоимости — оговорить в тексте.
- Влияние: core/order_quantity, gui, experiments/simulation.

## 2026-11-03 — Инструменты разработки: Python 3.12 + uv
- Решение: Python 3.12 (зафиксирован в .python-version), управление окружением и зависимостями — uv, сборка пакета — hatchling, линтер — ruff.
- Причина: под Python 3.14 не гарантированы колёса numba/statsforecast; uv даёт воспроизводимый lock-файл.
- Альтернативы: pip + venv (нет lock-файла), conda (тяжелее, хуже с PyInstaller).
- Влияние: весь проект, сборка .exe.

## 2026-11-03 — Пробная сборка .exe (PySide6 + statsforecast)
- Решение: связка PySide6 + statsforecast (numba) упаковывается PyInstaller без дополнительных настроек; основной вариант ETS остаётся statsforecast, запасной (statsmodels) не нужен.
- Результат проверки: сборка в режиме onedir ~5 мин; .exe открывает окно и считает AutoETS в фоновом потоке, прогноз совпадает с запуском из исходников. Размер папки ~475 МБ.
- Замечание: предупреждение PyInstaller об отсутствии tbb12.dll не мешает — это необязательный слой многопоточности numba.
- Открытый вопрос (Этап 7): уменьшить размер — исключить неиспользуемые модули Qt и библиотек.
- Влияние: packaging/, Этап 7.
